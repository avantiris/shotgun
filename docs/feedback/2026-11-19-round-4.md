### F4.4 Copy, paste and cut with Ctrl+C / V / X
- Said: "on the track I must be able to copy and paste tracks (not via right click but via ctrl c / v / x)."
- Kind: workflow
- Area: timeline
- Status: fixed (62447d8)
- Read as: the clips on a track (the selection), not whole tracks.
- Found: Ctrl+C was already bound, but the key never arrived. The window
  layer (egui-winit) turns Ctrl+C, X and V into clipboard events for text
  fields and drops the key press. The same had kept Ctrl+V from importing
  a link since M2. Now those keys arrive as keys unless a text field has
  focus.
- Now: Ctrl+C copies, Ctrl+X cuts (leaves the gap), Ctrl+V pastes the
  clips at the playhead, or imports if something else was copied since
  (07-ui-keybinds.md). A paste lands over what is in its place and keeps
  the clip's volume, fades and placement (it lost them before).
- Verified: headless flow `ctrl_c_x_and_v_copy_cut_and_paste_the_selected_clips`,
  unit test, and a hidden run of copy, cut and Ctrl+V through the shell.
- Not verified: the real key presses and the mark on the real clipboard.
  Automated runs may neither press keys nor write the clipboard on the
  desktop, so this one needs a person.
